## 2. Pinterest — ideas hubs are server-rendered (search feed is not)

**Key access finding:** logged-out `pinterest.com/search/pins/?q=…` hydrates *very* slowly, caps at ~23 pins, gives no pin permalinks and no alt text (all alts are literally "Pin"). Its internal `/resource/BaseSearchResource/get/` API returns **403 Invalid Resource Request** logged-out.
**But** `pinterest.com/ideas/<slug>/<id>/` pages are **server-rendered**: every pin's image hash is present in the raw HTML (~140–155 per hub), and each hub also lists ~23 sibling hub URLs. Thumbnail path `/236x/aa/bb/cc/<md5>.jpg` maps 1:1 to full-res `https://i.pinimg.com/originals/aa/bb/cc/<md5>.jpg`.

## 3. Reddit — new subs/queries only

**Key access finding:** in addition to `old.reddit.com/r/<sub>/search?q=…` + `get_page_text`, the **JSON API works from inside an old.reddit.com tab** via `javascript_tool`: `fetch('/r/<sub>/search.json?q=…&restrict_sr=1&sort=…&limit=50')` and `fetch('/comments/<id>.json?limit=30&sort=top')` both return 200. This gives titles, scores, comment counts, `media_metadata` gallery image ids and comment bodies in one round trip — far cheaper than page scraping. (`/gallery/<id>.json` → 404; use `/comments/<id>.json`.)
Gallery image URL = `https://i.redd.it/<media_metadata key>.<ext>`.
