### Key length rule found (ID, miinhair Jakarta — the clearest statement anywhere in SEA sources)
| Length | Digital perm | Cold perm |
|---|---|---|
| Short (above shoulder) | less ideal | ✓ recommended |
| **Medium (shoulder → collarbone)** | ✓ | ✓ |
| **Long (past collarbone)** | ✓ **recommended** | less ideal |
Rationale given: digital perm needs enough length to wrap the heated rod; heat penetrates heavier/longer strands and the wave "looks best when dry", so it holds naturally on long hair. → **For this user (chin→shoulder+), digital perm is the correct ask, and both work at exactly shoulder length.**

### Tool findings worth adding to `sources.md` §1
- **google.com is no longer usable as a link-harvest proxy in Chrome**: result links are rewritten to `/goto?url=<opaque>` and `javascript_tool` returns empty on google.com. `get_page_text` still gives titles+domains only. Use **WebSearch** for discovery instead.
- **bing.com/images IS the working image-URL route** in Chrome: `[...document.querySelectorAll('a.iusc')].map(e=>JSON.parse(e.getAttribute('m')).murl)` yields 40–70 original URLs per query. Scroll 5× first.
- **`javascript_tool` output is truncated ≈1000 chars and refuses any string containing a query-string/JWT-looking URL** ("BLOCKED: Cookie/query string data"). Workaround: `.split('?')[0]`, strip the common URL prefix, and page with `.slice(n,m)`.
- **`assets.unileversolutions.com` (allthingshair / allthingsbeauty, all locales) hard-blocks curl**: 403/406 regardless of UA, Referer, Accept, Sec-Fetch-* headers, and with or without `?im=` transform params. Names harvestable, images not.
- WebFetch 403 wall hit on: allthingshair/allthingsbeauty (all locales), vogue.co.th, watsons.co.th, salehere.co.th, blog.30shine.com, kiehls.com.vn, kompas.com, anhtoc.edu.vn. Chrome works for anhtoc + allthingsbeauty; not tried in Chrome for the rest.
- **lemon8-app.com article pages are WebFetch-readable for text** (no login wall) but expose no image URLs; `p16-va.lemon8cdn.com/*~tplv-tej9nj120t-origin.webp` URLs found via Bing Images download fine with a normal UA.
- Facebook/Instagram: not attempted (login wall, per brief).
